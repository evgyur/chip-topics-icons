# Public export boundary

This repository is a clean, class-level extraction of a topic-icon workflow, not a redacted copy of an operator's chat or finished internal brand system.

## Included

The root agent skill and installation guide; generic inventory/artwork/publication/application helpers; explicit environment configuration; the neutral existing-runtime adapter contract; original MIT synthetic vector examples; deterministic contract checks; prompt scenarios; local HTTP fixture tests. There is no automatic service, scheduler, account login, payment integration or GitHub Actions workflow.

## Intentionally excluded

Private chat names/messages/inventories, actual user/forum/topic/custom-emoji IDs, production credentials and `.env` files, account/session caches, personal paths, local service implementations and deployment wiring, original operational scripts, authenticated screenshots, private brandbooks and collected logo libraries. No source message excerpts or internal completion receipts are shipped. Synthetic identifiers in examples/tests are labelled as such.

## Portable adaptations

Hardcoded account/chat/path/token loading is replaced with explicit command arguments, a bounded-origin credential environment and an existing authenticated runtime contract. Task-specific design mappings become user-owned manifests. Topic names never enter published emoji-pack metadata. Original demo artwork replaces private/user-specific art and third-party logos; source/rights metadata and identity checks remain mandatory for real use.

Complete pack counts, decoded-pixel uniqueness, emoji-ID uniqueness, General preservation, expected-prior-value edits and eventual readback are retained. The bot is used only for the authorized pack operation and identity/rights checks; no account migration is implied.

## What the evidence means

Repository tests exercise synthetic account data through a local HTTP server, real multipart serialization, image rendering, resumability, conflict/stale-state handling and negative verification checks. They do not publish another user's emoji packs, test that user's Telegram privileges or establish the quality/licensing of logos obtained later. Production readiness still requires an authorized real run in the intended forum and exact readback.

MIT covers repository code and original synthetic examples. Logos and icons fetched for future runs retain their own licenses and trademark conditions; public availability alone is not redistribution permission. Private/customer/user art is not authorized for public export just because a reusable tool was requested.
